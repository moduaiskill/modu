# 공통 스킬 제작 규격

## 하나의 폴더, 하나의 업무

경로는 `skills/<분야>/<스킬명>/`입니다. 이름은 64자 미만의 영문 소문자·숫자·하이픈으로 작성하고 `SKILL.md`의 `name`과 일치시킵니다.

필수 파일은 `SKILL.md`입니다. 공통 frontmatter에는 `name`과 `description`을 넣습니다. 설명에는 무엇을 하고 언제 사용하는지 적습니다. 본문에는 필요한 입력, 업무 절차, 출력 형식, 중요한 제약을 담습니다.

```yaml
---
name: meeting-notes
description: 회의 메모에서 논의 내용, 결정 사항, 후속 할 일과 미정 항목을 구분한 회의록을 작성한다. 회의 기록 정리 요청에 사용한다.
---
```

## 선택 파일

| 경로 | 추가하는 경우 |
| --- | --- |
| `references/` | 용어, 평가 기준, 상세 절차를 필요할 때 읽을 경우 |
| `assets/` | 결과물에 사용할 양식이나 이미지가 있을 경우 |
| `scripts/` | 반복 계산이나 파일 변환 코드가 필요할 경우 |

필요한 파일만 만들고 `SKILL.md`에서 상대 경로와 읽는 시점을 안내합니다. 개별 스킬 폴더만 복사해도 동작하도록 외부 폴더에 의존하지 않습니다. 전용 명령은 공통 지침과 구분하고 도구가 없을 때 가능한 대안을 설명합니다.

## 제출 시 확인

- 사용자, 사용 근거, 기대 효용이 분명한가.
- 입력에 없는 사실·수치·담당자를 채워 넣지 않는가.
- 작성 안내를 실제 지침으로 모두 교체했는가.
- 참고자료가 포함되고 개인정보와 비공개 자료가 제거되었는가.
- 대표 입력과 불완전한 입력으로 확인했으며 출력 예시나 캡처가 있는가.
- 확인한 AI 도구·모델·날짜와 한계를 기록했는가. 미확인 도구를 검증 완료로 표시하지 않는가.
- 스크립트의 요구 환경, 실행 방법, 검증 결과가 있는가.

검수 전에는 예제 또는 제작 중으로 공개합니다. 최종 피드백을 반영한 뒤 배포 상태를 갱신합니다.
