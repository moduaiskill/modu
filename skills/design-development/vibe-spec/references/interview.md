# 묻는 법

## 절별 질문 문장

템플릿의 칸 이름을 그대로 읽어 주지 말고, 아래처럼 바꿔 묻는다. 괄호 안은 답이 막힐 때 던지는 보조 질문이다.

**한 줄로 말하면**
- "누가 이걸 왜 쓰는지 한 문장으로 말한다면 어떻게 되나요?"
- (막히면) "친구한테 자랑한다고 치면 뭐라고 말할 것 같으세요?"

**왜 만드나요**
- "지금은 이 일을 어떻게 하고 계세요?"
- "그중에 제일 귀찮은 순간이 언제예요?"
- 여기서 나오는 구체적인 불편이 나중에 요구사항이 된다. 대충 넘기지 않는다.

**누가 쓰나요**
- "실제로 쓸 사람 한 명만 떠올려 주세요. 누구예요?"
- (모두라고 하면) "그중에 제일 먼저 쓰게 될 한 사람은요?"
- "그분은 폰으로 보실까요, 컴퓨터로 보실까요?"

**쓰는 순서**
- "그분이 이걸 열었어요. 처음에 뭘 보게 되나요? 그다음엔요?"
- 세 단계까지만 받으면 충분하다. 여기서 화면 개수가 대강 정해진다.

**꼭 있어야 하는 것**
- "이것 하나가 안 되면 아예 안 쓰겠다 싶은 게 뭐예요?"
- "그게 됐다는 걸 어떻게 아세요? 화면에서 뭐가 보이면 된 거예요?"
- 두 번째 질문을 꼭 한다. 완료 기준은 이 질문에서만 나온다.

**안 만들 것**
- "지금 떠오르지만 이번엔 안 할 것 두 가지만 정해 볼까요?"
- (막히면) "회원가입, 결제, 알림, 검색 중에 이번에 없어도 되는 게 있을까요?"
- 비전공자가 가장 어려워하는 칸이다. 선택지를 주면 훨씬 잘 답한다.

**정보**
- "이 안에 남의 이름이나 연락처가 들어가나요?"
- "지금 쓰시는 엑셀이나 메모가 있나요?"

**겉모습**
- "비슷한 느낌으로 만들고 싶은 앱이나 사이트가 있나요?"
- 없다고 하면 넘어간다. 이 칸은 비어도 만들 수 있다.

**사정**
- "언제까지 필요하세요?"
- "이걸 누구한테 보여 줄 건가요? 나만 쓰나요, 링크를 주나요?"
- "매달 돈이 조금 드는 방법도 괜찮으세요, 무료로만 하고 싶으세요?"

**이게 되면 끝**
- "어떤 장면을 보면 '다 됐다' 하실 것 같으세요?"

## 전문용어 바꿔 말하기

질문에는 왼쪽 말을 쓰지 않는다. 오른쪽처럼 묻는다.

| 쓰지 않는 말 | 대신 이렇게 |
|---|---|
| 데이터베이스 | 적어 둔 게 사라지지 않고 남는 곳 |
| 배포 / 호스팅 | 남들이 링크로 들어올 수 있게 올려 두는 것 |
| 인증 / 로그인 | 아무나 못 들어오게 막을지 |
| API 연동 | 다른 서비스에서 정보를 받아오는 것 |
| 반응형 | 폰에서도 화면이 안 깨지게 |
| 프론트엔드 / 백엔드 | 보이는 화면 / 뒤에서 처리하는 부분 |
| 스키마 / 모델링 | 무엇을 어떤 항목으로 적어 둘지 |
| MVP | 처음에 딱 이만큼만 만들어서 써 보는 것 |
| 마이그레이션 | 지금 쓰던 자료를 옮기는 것 |
| 캐싱 / 최적화 | 더 빠르게 만드는 것 |

## 모른다고 할 때의 기본값

정해 주되 반드시 **정했다고 말하고 바꿀 수 있다고 알린다.** 아래는 혼자 만드는 작은 프로젝트 기준이다.

| 칸 | 기본값 | 함께 할 말 |
|---|---|---|
| 어디에 올릴지 | 링크를 아는 사람만 들어오는 공개 웹 | "비밀번호는 나중에 붙일 수 있어요" |
| 로그인 | 만들지 않음 | "로그인을 넣으면 만들 것이 두 배로 늘어납니다" |
| 저장 | 가장 간단한 방법으로 시작 | "쓰다가 부족하면 그때 옮기면 됩니다" |
| 기기 | 폰 먼저 | "폰에서 잘 되면 컴퓨터에서도 대개 괜찮습니다" |
| 디자인 | 기본 형태로 시작 | "내용이 정해지면 겉모습은 금방 바꿉니다" |
| 사람 수 | 몇십 명 규모 | "많이 몰리면 그때 손보면 됩니다" |

## 대답을 받은 뒤

- 되돌려 확인한다: "정리하면 ○○이군요. 맞나요?"
- 요구사항이 다섯 개를 넘으면 순위를 매기게 한다: "하나만 된다면 어느 것부터요?"
- 완료 기준이 추상적이면 다시 묻는다: "그게 됐는지 화면에서 어떻게 확인하세요?"
- 사용자가 기능을 계속 추가하면 그 자리에서 "있으면 좋은 것"으로 옮겨 적고 그렇게 했다고 알린다.
