# 공공 입찰 제안서 (정식 판 · 범용)

## 사용 환경

본문 지침과 HTML 양식은 Claude와 GPT 계열 도구에서 참고할 수 있다. 파일 생성, Python 실행, PDF 변환 지원은 환경별로 다르다. HTML만 만들 수 있으면 브라우저 인쇄로 PDF를 저장하도록 안내한다. 모든 모델에서의 동작을 검수한 스킬이라는 의미는 아니다.

경로는 이 `SKILL.md`가 있는 폴더를 기준으로 해석한다. 이미지 압축에는 Pillow(HEIC는 추가로 pillow-heif), 자동 PDF 생성에는 WeasyPrint와 운영체제별 실행 의존성이 필요하다. `make_pdf.py`의 쪽 번호 검사에는 Poppler의 `pdftotext` 명령도 필요하다. 준비되지 않은 도구를 실행했다고 주장하지 않는다.

공모·입찰·시담에 내는 **정식 제안서**를 단일 HTML 파일로 만든다. 브라우저에서 열어 읽고,
인쇄(Ctrl+P) 한 번으로 제출용 A4 PDF가 나온다.

`assets/template.html`을 복사해 시작한다. 서식(표지·대제목·표·쪽 번호·글꼴)은 관공서 제출본
관례를 따른 **기본값**이다 — 이유 없이 색·치수·글꼴을 바꾸지는 않되, 아래 「발주처 양식 우선
원칙」이 걸리면 그쪽에 맞춘다.

## 발주처 양식 우선 원칙 — 융통성 있게

이 문서는 정부·공공기관 심사위원이 읽는다. 그들이 매일 보는 서식(개조식·관공서 표·담백한
제목)에 가까울수록 읽기 편하고, 발주처가 양식을 지정했다면 그 양식이 곧 정답이다.

- **공고문·제안요청서가 목차, 번호 체계, 분량, 표 서식, 어투를 지정하면 무조건 그쪽을 따른다.**
  6대 영역·표지·대제목은 지정이 없을 때의 기본값일 뿐이다.
- 발주처가 배포한 서식 파일(HWP 등)에 채워 넣으라는 공고면 이 스킬은 맞지 않다. HTML로 새로
  만드는 것이 아니라 배포 양식을 채우는 작업임을 사용자에게 알리고 확인받는다.
- 지정이 없더라도, 발주처가 관례적으로 쓰는 패턴(개조식 어투, ※ 출처 표기, (단위 : 원) 표기,
  역할분담표 등)이 확인되면 적극 반영한다. 참고할 기존 제출본이 작업 폴더에 있으면 먼저 읽고
  그 문서의 어투·표 패턴에 맞춘다.
- 표지·쪽 번호 같은 공통 요소도 발주처 표지 양식이 따로 있으면 교체한다.

## 0. 먼저 — 기관 정보 파일을 확보한다

Ⅰ절(제안기관 현황)은 제안서마다 달라지지 않는 **기관 고정 정보**다. 이 스킬은 그 정보를
템플릿에 박아 두지 않고 별도 파일에서 가져온다.

1. **`assets/organization-profile.md`가 있으면** 그것을 읽고 Ⅰ절과 Ⅱ~Ⅵ절의 근거로 쓴다.
   기관 사실관계(수치·실적·인력)는 여기서만 가져오고 **지어내지 않는다.**
2. **없으면** `assets/organization-profile.template.md`를 복사해 만든다. 작업 폴더에 기관
   소개서·기존 제안서·홈페이지 자료가 있으면 먼저 읽어 자동으로 채우고, **비는 항목만
   사용자에게 물어본다.** 한 번에 다 묻지 말고 아래 순서로 묶어서 묻는다.
   - (1순위 · 없으면 제안서를 못 씀) 기관명·대표자·설립일·소재지·구성원 수·홈페이지
   - (2순위 · 평가 배점 직결) 유사 사업 수행 실적, 참여 인력, 핵심 역량 3가지
   - (3순위 · 있으면 좋음) 시설·장비, 자체 플랫폼·시스템, 대표 행사, 로고 파일
3. 채운 파일은 작업 폴더에도 사본을 남겨 **다음 제안서에서 재사용**하도록 안내한다.
   Ⅰ절을 한 번 완성해 두면 이후 제안서는 그 두 `<section>`을 복사해 쓰면 된다.

**`organization-profile.md` §12 「표준 인용 수치」를 먼저 본다.** 누적 교육생·실적 건수 같은
숫자는 문서마다 달라지면 신뢰를 잃으므로 이 표 값으로 통일한다.

## 1. 공고문(RFP)을 읽는다 — 제안서는 공고문에 대한 답이다

제안서 작성의 출발점은 언제나 공고문이다. 작업 폴더의 제안요청서·과업지시서·공고문 PDF를
읽어 다음을 정리한다.

- 사업명·목적·배경, 사업기간, 예산 규모(공개 시)
- 과업 범위와 요구사항(대상·규모·시수·성과지표·산출물)
- **제안서 평가 기준과 배점** — 있으면 반드시 확보한다. 배점이 큰 항목을 본문에서 두껍게
  쓴다(이게 당락을 가른다)
- 참가 자격, 제출 형식·분량 제한

공고문이 요구한 항목은 **하나도 빠뜨리지 않는다.** 요구사항 목록을 만들어 제안서 절과
대응시키고, 각 요구를 어느 절에서 답했는지 스스로 점검한다.

## 2. 문서 구조 — 6대 영역

| 영역 | 소절 | 채우는 방법 |
|---|---|---|
| Ⅰ 제안기관 현황 | 1. 일반현황 / 2. 기관 주요 역량 | **`organization-profile.md`에서 옮겨 채운다.** 공고문 요건에 맞게 실적 강조·취사선택 |
| Ⅱ 제안 개요 | 1. 과업에 대한 이해도 / 2. 과업 추진 전략 | 공고문 배경·목표를 우리 언어로 재정리 + 우리 강점과 연결 |
| Ⅲ 과업 수행계획 | 1. 과업 접근 방법 / 2. 세부 수행계획 | 커리큘럼·운영 방식 등 구체 실행 계획 |
| Ⅳ 조직 및 인력 | 1. 수행 조직 구성 / 2. 투입인력 및 역할 / 3. 인프라 활용 | 조직도(SVG) + Ⅰ-2.4 인력에서 투입 인력 선정 |
| Ⅴ 사후관리 | 1. 교육 성과평가 / 2. 환류 및 확산 | 성과지표·측정 방법·환류 계획 |
| Ⅵ 사업관리 | 1. 일정관리 / 2. 품질관리 / 3. 위험관리 | 단계별 일정표 + 품질·위험 대응 |

- 이 6대 영역은 관공서 제안서에서 널리 쓰는 목차다. 공고문이 다른 목차를 요구하면 그에 맞춰
  절을 더하거나 빼고 **로마자를 다시 매긴다.** 목차(순서)도 같이 맞춘다.
- Ⅰ절은 기관 현황이라 분량이 크다(보통 4~6쪽). Ⅱ~Ⅵ이 실제 제안의 핵심이다.
- **목차 쪽 번호는 본문을 완성한 뒤 마지막에 채운다.** 템플릿에 `{{n}}`으로 비워 두었으니
  인쇄 미리보기나 `make_pdf.py`로 실제 쪽을 보고 적는다.

## 3. 번호 체계 — 정부 개조식 6단계, 제목에 번호를 직접 쓴다

정부 사업계획서·제안서에서 널리 쓰는 위계 그대로다. 템플릿 CSS와 짝이므로 태그를 지킨다.

| 단계 | 태그/클래스 | 예 |
|---|---|---|
| 대제목 | `<h2><span class="num">Ⅱ</span><span class="txt">제안 개요</span></h2>` | Ⅱ 제안 개요 |
| 1. | `<h3>` | 1. 과업에 대한 이해도 |
| 1.1 | `<h4>` | 1.1 사업 배경 및 필요성 이해 |
| 가. | `<h5>` | 가. 기관 현황 |
| ㅇ | `<ul class="circle"><li>` | ㅇ (지역한계) 지역 내 AI 인프라 부족 |
| - | `<ul class="dash"><li>` | - 세부 항목 |
| · | `<ul class="dot"><li>` | · 보충 세부(필요할 때만) |
| □ 묶음 | `<ul class="box"><li>` | □ 핵심 역량 |
| ※ 출처·비고 | `<p class="note">※ …</p>` | ※ 2025 수요조사(자체) |

- 번호(1., 1.1, 가.)는 **제목 문자열에 직접 쓴다.** ㅇ·-···□는 CSS가 자동으로 붙이므로
  글에 다시 쓰지 않는다. 소절이 더 깊어야 하면 1.2.1(h4에 그대로 표기)도 쓸 수 있다.
- 대제목은 로마자 뒤에 마침표를 찍지 않는다(`Ⅱ 제안 개요`). 목차에서만 `Ⅱ. 제안 개요`.
- 한 대제목 절이 여러 쪽으로 이어지면, 이어지는 쪽의 h2에 `<span class="sub">(계속)</span>`을
  붙여도 된다(템플릿 Ⅰ-2 참고).

## 4. 서술 원칙 — 정부 개조식으로 쓴다

이 문서의 어투는 **정부 개조식**이다. "~한다 / ~할 예정이다 / ~합니다" 같은 서술형 문장을
쓰지 않는다(발주처 양식이 서술형을 요구하는 예외만 인정).

- **종결은 명사형이 기본.** `~필요` / `~구축` / `~확보` / `~제고` / `~마련` / `~운영`처럼
  명사로 끊는다. 조금 긴 설명 문장은 `~함` 종결(`~설계함` / `~운영함` / `~수립함`)을 쓴다.
  한 항목 안에서 명사형과 `~함`을 섞어도 되지만, `~한다`·`~입니다`는 금지.
- **(괄호 키워드) 라벨을 적극 쓴다.** ㅇ·- 항목의 첫머리에 2~6자 키워드를 괄호로 붙여
  훑는 심사위원이 구조를 바로 잡게 한다. 마크업은 `<b class="kw">(운영역량)</b>`.
- **※로 출처·근거를 단다.** 수치·조사 결과 뒤에는 `※ 재직자 교육 수요조사(2025.04~05, 자체)`
  처럼 출처를 붙인다(`p.note`).
- **예문**(개조식 어투 참고용 — 내용은 각자 기관 것으로 바꾼다):

  ```
  ㅇ (지역한계) 해당 지역 AI 공급기업 등록 수 전국 하위권으로 디지털 인력 수급
     불균형이 심각하나, 재직자 다수가 AI 실무 적용을 희망하고 있어 훈련 인프라 시급
   - (운영역량) 전담팀 신설, 협약기관 n개 확보 및 수요조사 완료 등 즉시 운영
     가능하며, 상근 전문인력을 기반으로 안정적·지속가능한 운영을 책임 있게 수행
   - (선정 절차) 후보군을 발굴하고, 경영진 인터뷰로 참여 의지를 확인한 뒤, 전담인력
     합동 심사를 거쳐 n개 기관을 최종 선정함
  ※ 출처 기관명 및 조사 시점을 반드시 명시
  ```

- **공고문 요구 ↔ 기관 강점 매칭.** "다양한 경험 보유" 같은 추상어 대신 프로필 파일에 적힌
  **구체 수치**(누적 교육생 수, 실적 건수·규모, 상근 전문인력 수)로 쓴다.
- **평가 배점이 큰 항목을 두껍게.** 이해도·수행계획·사후관리 배점이 크면 그 절을 늘린다.
- 근거 없는 형용사("최고의", "완벽한")는 쓰지 않는다. 프로필 파일에 없는 사실은 지어내지
  않고, 확정 안 된 것은 `{{ }}`로 남겨 사용자에게 확인한다.

## 5. 그림과 강조 컴포넌트

### 5.1 이미지

기관 조직도·성과 요약·행사 사진 등을 넣으려면 HTML 옆에 `images` 폴더를 만들어 파일을 두고
`<figure class="diagram"><img src="images/파일명.png" alt="…"><figcaption>[그림] …
</figcaption></figure>` 형식으로 참조한다. 템플릿에는 이미지 자리를 주석으로 표시해 두었다.

**이미지 크기 — 본문 폭 전체(170mm)가 기본이다.** 안에 글자가 들어 있는 이미지(통계·조직도)는
축소하면 읽히지 않는다. 템플릿 CSS가 `figure.diagram img`를 170mm로 잡아 두었으니 인라인
`style="max-width:…"`로 줄이지 말 것. 글자가 없는 그림만 `<figure class="diagram narrow">`
(120mm)를 쓴다. 완성 후 인쇄 미리보기에서 이미지 안 글자가 읽히는지 눈으로 확인한다.

**이미지가 보이려면 둘 중 하나를 한다.**

- (인쇄·PDF만 할 때) 완성 HTML **옆에 `images` 폴더를 같이 둔다.** 상대경로로 참조하므로
  브라우저·크롬 렌더에서 그림이 보인다. HTML을 옮길 때 폴더도 함께 옮긴다.
- (HTML 자체를 메일로 보낼 때) 그림까지 파일 하나에 담으려면 임베드한다.

  ```bash
  python3 scripts/embed_images.py 제안서.html
  ```

  로컬 `<img>`를 data URI로 바꿔 넣어 **그림 포함 단일 파일**이 된다(로고는 embed_logo.py가
  따로 처리). 단, 이미지가 커서 파일 용량이 늘어난다.

### 5.2 인라인 SVG 다이어그램

이미지가 없어도 벡터로 직접 그릴 수 있다. 템플릿에 **조직도**(Ⅳ-1)와 **과업 추진 전략
개념도**(Ⅱ-2)가 들어 있으니 상자 안 문구만 바꾸면 된다. 추가는 `<figure class="diagram">
<svg viewBox="0 0 W H">…</svg><figcaption>…</figcaption></figure>` 형식. 색은 CSS 변수와
같은 값(기본 `#00468c`·`#99cc00`)을 쓰고, SVG 폰트는 `font-family="'Malgun Gothic',sans-serif"`.
자주 쓰는 것: 추진 일정 타임라인, 교육과정 흐름도, 시스템 구성도. 테두리를 두르려면
`<figure class="diagram framed">`.

### 5.3 강조 컴포넌트 — 선택 장치, 기본은 절제

문서의 기본 톤은 **담백한 관공서식**이다. 정부 심사위원이 매일 보는 서식에서 벗어날수록
오히려 이질감을 주므로, 아래 컴포넌트는 "글이 길어질 때마다"가 아니라 **꼭 필요한 자리
몇 곳에만** 골라 쓴다. 기준: KPI 스트립은 Ⅰ 도입 1회, 콜아웃은 문서 전체 한두 곳,
요구↔대응 매트릭스는 배점표가 있으면 필수 — 나머지는 없어도 된다. 색은 표준 3색만,
면 채움 없이 선 위주로 쓴다(템플릿 CSS가 이미 그렇게 되어 있다).

| 컴포넌트 | 마크업 | 쓰는 곳 |
|---|---|---|
| KPI 스트립 | `<div class="kpi"><div><b>1,200명</b><span>누적 교육생</span></div>…</div>` | Ⅰ 도입부 1회. 규모를 3초 안에 보여줄 때만 |
| 단계 바 | `<div class="steps"><div>사전 준비</div><div class="on">교육 운영</div>…</div>` | 수행 흐름 한 줄 요약. Ⅲ-1에 기본 배치. `.on`이 강조 단계 |
| 콜아웃 | `<div class="callout"><b class="t">제목</b>본문</div>` | 차별화 포인트·핵심 약속. **문서 전체 한두 곳만.** 초록판은 `class="callout g"` |
| 배지 | `<span class="badge">필수</span>` `<span class="badge g">가점</span>` | 공고문에 필수/가점 구분이 명시된 경우에만 |
| 수치 강조 | `<span class="nm">1,200명</span>` / `<span class="hl">수료율 96%</span>` | 근거 수치에만. `.nm`은 진한 색 굵게, `.hl`은 형광 밑줄 |
| 요구↔대응 표 | `<table class="small match">` + `td.req`(요구) `td.sec`(해당 절) | Ⅱ-1.2에 기본 배치. **평가표가 있으면 반드시 채운다** |
| 2단 배치 | `<div class="cols"><div>…</div><div>…</div></div>` | 그림+설명, 표 두 개를 나란히. 한 쪽에 들어갈 때만 |
| (키워드) 라벨 | `<b class="kw">(운영역량)</b>` | ㅇ·- 항목 첫머리. 개조식의 기본 장치라 자유롭게 쓴다 |
| 단위 표기 | `<p class="unit">(단위 : 원)</p>` | 예산·수치 표 바로 위 우측 정렬(정부 서식 관례) |

**요구↔대응 매트릭스가 이 스킬에서 가장 중요한 표다.** 공고문 요구를 왼쪽에 그대로 옮기고,
대응 방안과 답한 절 번호를 오른쪽에 짝지으면 "요구를 하나도 안 빠뜨렸다"가 한눈에 증명된다.
요구 개수만큼 행을 늘리고, 본문 절 번호와 실제로 맞는지 마지막에 대조한다.

## 6. 인쇄(A4 PDF) 품질

템플릿 CSS에 반영되어 있다. 편집하다 깨뜨리지 않도록 원리를 알아 둘 것.

- **브라우저 기본 머리글/바닥글 제거**: `@page` margin box에 `content:""`. `content:none`은
  기본 바닥글을 되살리므로 반드시 빈 문자열을 쓴다.
- **쪽 번호**: 표지·목차엔 번호 없이 본문 첫 장을 1쪽으로 시작해 끝까지 연속. 번호 없는
  앞쪽(`.cover, .toc`)에서 `counter-reset:page 0`으로 카운터를 되돌리는 방식이다. 본문 첫
  절에 `counter-reset`을 걸면 그 절이 두 쪽 넘어갈 때 번호가 끊기니 하지 말 것.
- **제출 전 쪽 번호 기계 검사**:

  ```bash
  python3 scripts/make_pdf.py 제안서.html
  ```

  (`pip install weasyprint --break-system-packages` 필요. 없으면 헤드리스 크롬으로
  `chrome --headless=new --disable-gpu --no-pdf-header-footer --print-to-pdf="출력.pdf" "file:///….html"`)
- **잘림 방지**: `tr{break-inside:avoid}`, `thead{display:table-header-group}`,
  `figure.diagram{break-inside:avoid}`, `h2{break-after:avoid}`. 한 쪽보다 긴 표에는
  `break-inside:avoid`를 걸지 말 것.
- 각 대제목 절은 `class="pagebreak"`로 새 쪽에서 시작한다.

## 7. 서식 규칙 — 표준 기본값

발주처 지정 서식이 없으면 이 값을 그대로 쓰고, 지정 서식이 있으면 「발주처 양식 우선 원칙」에
따라 그쪽에 맞춘다.

| 항목 | 값 |
|---|---|
| 지면 | A4, 여백 상 25 / 좌우 20 / 하 18mm, 본문 폭 170mm |
| 본문 | 함초롬돋움 12.5pt, 줄간격 1.6, 자간 -0.01em |
| 표지 3색 띠 | 높이 1.3mm, 노랑 `#f7cb0c` 30% · 초록 `#92c73e` 40% · 파랑 `#2192cf` 30% |
| 표지 제목 | 한컴바탕(명조 계열) 29pt, 『사업명』제안서 (겹낫표 사용) |
| 표지 굵은 선 | `#303192`, 높이 1.1mm |
| 표지 연월 | HY헤드라인M 20pt, `2026. 7.` 형식 |
| 대제목 | 상단 액센트 2.1mm(초록+하늘), 띠 11.4mm, 로마자 박스 11.9mm, 진한 파랑→흰색 그라데이션, HY헤드라인M 18pt |
| 표 | 검정 실선, 머리행·좌측 라벨열·합계행 `#e5e5e5`, 줄무늬 없음 |

**색을 기관 브랜드로 바꾸려면** 템플릿 맨 위 `:root`의 변수 6개만 고치면 문서 전체가 따라간다.
`--navy`(대제목·강조) / `--accent`(대제목 상단 초록) / `--band`(대제목 상단 하늘) /
`--cover-rule`(표지 굵은 선) / `--cover-y`·`--cover-g`·`--cover-b`(표지 3색 띠).
`--navy`는 흰 글씨가 얹히므로 반드시 진한 색으로 둔다. 나머지 치수는 건드리지 않는다.

**소제목은 정부 문서처럼 담백하게.** `h3`(1.)·`h4`(1.1)·`h5`(가.) 모두 색 배경·색 바 없이
굵기·크기·들여쓰기로만 위계를 잡는다(발주처가 매일 보는 개조식 서식과 톤을 맞춘 의도된
선택이다). 위계는 번호 체계와 (키워드) 라벨이 대신 잡아 준다.

- **표지 로고**: `LOGO_PLACEHOLDER`를 마지막에 치환한다.

  ```bash
  python3 scripts/embed_logo.py 제안서.html --logo 기관로고.png
  ```

  로고를 `assets/logo.png`로 두면 `--logo` 없이도 잡힌다. data URI로 박아 넣으므로 메일로
  오가도 표지가 깨지지 않는다. **로고 파일이 없으면** 표지의 `<img class="logo">` 줄을 지우고
  기관명만 둔다.
- **글꼴은 `--font-body`/`--font-head`/`--font-serif` 세 변수로만 관리한다.** 함초롬돋움(본문)
  · HY헤드라인M(대제목·목차·표지 연월·기관명) · 한컴바탕(표지 제목). 한글(HWP)이 깔린 PC에는
  모두 있어 HWP 제출본과 같은 인상을 주고, 없는 PC에서는 맑은 고딕·바탕으로 내려간다. 시스템에
  설치된 글꼴을 참조만 하므로 재배포·임베딩과 무관하다.
- **표지에 `height` 고정 금지**(빈 쪽 생김). **대제목 제목은 10자 안팎으로 짧게**(흰 글씨가
  띠 밝은 구간까지 넘어가면 안 읽힘). 부가 정보는 `.sub`로 뺀다.
- 완성되면 파일 경로, 인쇄 방법(버튼 → PDF로 저장), 로고 삽입, 목차 쪽 번호 확인을 안내한다.

## 8. 작업 순서 요약

1. **기관 정보 파일을 확보한다**(§0). 없으면 템플릿을 복사해 사용자에게 물어 채운다.
2. 공고문(RFP)을 읽고 요구사항·평가배점·**지정 양식 유무**를 정리한다. 작업 폴더에 기존
   제출본·참고문서가 있으면 그 문서의 어투·표 패턴을 먼저 확인해 맞춘다.
3. `assets/template.html`을 복사한다. 표지의 기관명·사업명·연월을 채운다.
4. **Ⅰ절을 기관 프로필로 채운다.** 공고문 요건에 맞는 실적·역량을 앞으로 당기고 무관한 항목은
   뺀다. KPI 스트립 숫자는 프로필 §12 「표준 인용 수치」와 일치시킨다.
   (이미 완성해 둔 Ⅰ절이 있으면 그 두 `<section>`을 그대로 복사해 붙인다.)
5. **Ⅱ-1.2 요구↔대응 매트릭스를 먼저 채운다.** 여기서 요구 누락이 잡히면 뒤 절 구성이 바뀐다.
6. Ⅱ~Ⅵ절의 `{{ }}`를 공고문 + 기관 프로필 근거로 채운다. 배점 큰 절을 두껍게. 어투는 §4
   개조식(명사형·`~함` 종결, (키워드) 라벨, ※ 출처). 공동수행·예산 제출이 있으면 템플릿 Ⅵ절의
   주석 처리된 **역할분담표·산출내역표 패턴**을 풀어 쓴다.
7. 조직도·추진전략도 SVG의 문구를 과업에 맞게 손보고, 쓸 이미지가 있으면 §5.1대로 넣는다.
   긴 절에는 §5.3의 강조 컴포넌트를 한 쪽에 하나꼴로 얹는다.
8. 로고를 심는다(`embed_logo.py`). 이미지를 파일에 포함하려면 `embed_images.py`도 돌리거나,
   완성 HTML 옆에 `images` 폴더를 같이 둔다.
9. `make_pdf.py`로 쪽 번호를 검사한 뒤 목차의 `{{n}}`을 실제 쪽 번호로 채운다.
10. 확정 안 된 수치(예산·강사·일정)는 지어내지 말고 사용자에게 확인한다.

### 제출 전 점검표

- [ ] 공고문 요구사항이 Ⅱ-1.2 매트릭스에 **하나도 빠짐없이** 들어갔고, 적어 둔 절 번호가 실제 본문과 맞는가
- [ ] 어투가 개조식으로 통일됐는가 — `~한다`·`~합니다`·`~할 예정이다` 서술형 잔재 검사
      (`grep -oE '(한다|합니다|예정이다)[.。]?</' 제안서.html`), 발주처가 서술형 양식을 지정한 경우는 예외
- [ ] `{{ }}`가 하나도 남아 있지 않은가 (`grep -o '{{[^}]*}}' 제안서.html`) — 목차 쪽 번호 `{{n}}` 포함
- [ ] 기관 수치가 `organization-profile.md` §12 표준값과 같은가
- [ ] 목차 쪽 번호가 실제 PDF 쪽과 맞는가
- [ ] 표지 로고가 data URI로 박혀 있는가 (`LOGO_PLACEHOLDER` 잔존 여부 확인)
- [ ] 표·그림이 쪽 경계에서 잘리지 않는가

## 9. 개인정보 주의

Ⅰ-2.4 교·강사진(참여인력)과 Ⅳ-2 투입인력에는 **실명·경력이 들어간다.**

- 본인 동의를 받은 범위에서만 적는다.
- 발주처 제출용으로만 쓰고, 외부 공개(홈페이지·블로그·공개 저장소)에는 성명을 `ㅇㅇㅇ` 등으로
  가린 버전을 따로 만든다.
- `organization-profile.md`도 인력 정보를 담고 있으므로 공개 저장소에 올리지 않는다.
  이 점을 사용자에게 한 번 알린다.
